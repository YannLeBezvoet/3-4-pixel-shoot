# 0011. Bots as input-producing utility-AI controllers

- Status: Proposed
- Date: 2026-11-03

## Context

Bots fill matches in solo and online, up to 63 of them. Basic intelligence first (move, aim, shoot, take cover), designed to be enriched later. They must run on the server with a bounded CPU cost and should not cheat in ways players notice.

## Options considered

### Integration

- **Bots that manipulate the world directly.** Simple at first, but they get different rules from players and diverge from the network path.
- **Bots that produce `InputCommand`s.** Same rules, same code path as humans; a bot can take over a disconnected player's character.

### Decision model

- **Finite state machine.** Easy to start; transitions multiply as behaviors are added.
- **Behavior trees.** Very flexible; more machinery and harder to tune for a small team.
- **Utility AI.** Each candidate action gets a score from simple considerations (distance to enemy, health, ammo, exposure…); the best action runs. New behaviors are new actions and considerations, without rewiring existing ones.
- **GOAP / planners.** Powerful; overkill for an arcade shooter.

### Navigation

- **A\* on the tile grid**, with clearance for the character radius and path smoothing.
- **Flow fields.** Efficient when many agents share a target; useful later for co-op waves.

## Decision

- Bots are **`BotController`s producing `InputCommand`s**, scheduled by `MatchHost`.
- **Perception** limited to what the bot could see (range, line of sight) and hear (gunfire and explosion events within a radius).
- **Utility AI** with initial actions: wander, engage, chase, reload; take cover added with the cover mechanic in milestone 2.
- **A\*** on the grid with cached paths; flow fields considered for the co-op mode.
- **Bounded cost:** decisions at ~10 Hz staggered across ticks; aim smoothing every tick; path requests time-sliced.
- **Difficulty** expressed as parameters (reaction delay, aim error, think rate, perception range).

## Consequences

- Bot behavior is testable with scenario tests on ASCII maps ("under fire, the bot reaches a position hidden from the attacker within N seconds").
- Bot randomness uses its own PRNG stream, so adding a bot behavior does not change unrelated simulation outcomes in tests.
- Utility scores need tuning; a debug overlay showing each bot's scores is planned.
