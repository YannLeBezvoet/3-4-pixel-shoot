# 0004. DOM menus with Preact, HUD in PixiJS

- Status: Accepted (2026-11-03)
- Date: 2026-11-03

## Context

The game needs menus (main menu, solo setup, room creation and join by code, lobby, settings including language) and an in-game HUD (health, ammo, grenades, kill feed, scores, timers, names over characters). All text comes from translations. The HUD must look pixel-exact and stay in palette; menus need text input, focus handling and layouts that adapt to text length in different languages. Mode settings should be shown by a generic form built from the mode's settings schema.

## Options considered

- **Everything in canvas.** Uniform look, palette-exact. But text input, focus, keyboard navigation, accessibility and long-text layout must all be rebuilt by hand.
- **Everything in DOM.** Easy layout and input. But the HUD would drift from the game frame (world-anchored names and health bars), and browser text anti-aliasing produces off-palette pixels.
- **DOM menus + canvas HUD.** Each part uses the tool that fits it.

For DOM menus:

- **Vanilla DOM.** No dependency, but manual state syncing grows fast in a lobby with live updates.
- **Preact (+ signals).** ~4 KB, JSX type-checked by TypeScript, no extra compiler.
- **Svelte / Solid.** Excellent, but add a compiler or a different reactivity model to learn.
- **React.** Heavier than needed.

## Decision

- **Menus in DOM with Preact** (and `@preact/signals` for state), styled with a pixel font and scaled with the same integer factor as the canvas.
- **HUD in PixiJS** at internal resolution, using a **bitmap pixel font** whose glyphs are palette colors.
- Mode settings forms and HUD widgets are **generic**, driven by data the mode exposes (settings schema, public mode state).

## Consequences

- Two UI technologies to know; the split rule is simple: *in-match overlay = Pixi, everything else = DOM*.
- Menu text may show slight anti-aliasing (off-palette edge pixels) depending on browser and font; see open questions.
- Adding a mode usually needs no UI code; a mode needing a special HUD widget can register one through a client registry (planned for milestone 5).
