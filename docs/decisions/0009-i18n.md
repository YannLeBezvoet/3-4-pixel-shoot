# 0009. Translations with i18next, languages as files

- Status: Proposed
- Date: 2026-11-03

## Context

The player chooses the language; French and English first. No displayed text is hard-coded. Adding a language means adding a file, with no code. Theme texts are translatable the same way. The server and simulation run without a language.

## Options considered

- **Custom tiny library** (key lookup, interpolation, `Intl.PluralRules`). No dependency; we would reimplement fallback chains, namespaces and plural rules.
- **i18next.** Mature, small, platform-agnostic; namespaces, fallback languages, interpolation and plurals built in; resources can be added at runtime (hot reload).
- **FormatJS / ICU MessageFormat.** Very expressive (select, plural, nested), heavier, more complex for translators.

## Decision

- **i18next** with its standard JSON format.
- **UI strings:** `locales/<lang>.json`. **Theme strings:** `themes/<id>/locales/<lang>.json`, loaded as namespace `theme.<id>`.
- **Discovery:** the client build lists the files found (Vite glob); the server and tools read the folders. Each file carries its display name (`"_meta": { "name": "Français" }`), so the language menu needs no code.
- **Default language:** the browser's preferred language if available, otherwise English; the choice is saved in the browser.
- **Fallback:** English. Missing keys are reported by `npm run check:i18n` (key parity against English), and by the theme validator for theme files.
- **No literal strings in UI code:** an ESLint rule rejects string literals in JSX and HUD text calls.
- **Server and simulation emit keys and parameters**, never text; parameters referring to players, weapons or maps are resolved to localized names on the client.
- **Font coverage check:** every character in every locale must exist in the game's bitmap font.

## Consequences

- Adding a language: add `locales/<lang>.json` and each theme's `locales/<lang>.json`; run the checks. A guide documents it.
- Languages with characters outside the font's coverage (e.g. CJK) also require a font with those glyphs; the coverage check makes that explicit (see open questions).
- i18next interpolation must be configured to not escape for canvas text and to escape for DOM text.
